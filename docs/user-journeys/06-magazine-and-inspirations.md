# 06 — Magazine & Inspirations

The Magazine is TripJam's destination-guide surface: editorial city cards (writeup, highlights, food, tips) generated by the `city-deep-dive` edge function (Haiku 4.5) and persisted in `trips.magazine_digest`, with photos sourced free from Wikipedia/Wikimedia via `src/photos.js`. It has two sub-tabs — **Inspirations** (default): a web-search-backed reading list of recent articles/vlogs from named individual creators, powered by `generate-destination-research` (Haiku 4.5 + `web_search`), cached server-side in `destination_research` and per-trip in `trips.inspirations_digest`; and **Magazine**: the city-card guide. Loading is deliberately lazy: on RG completion the app eagerly loads Inspirations plus at most 2 country-level deep dives, everything else loads via `IntersectionObserver` as cards scroll into view.

## Routing and naming

- The internal tab key for the Magazine surface is the legacy name **`brainstorm`**. Post-IG, the bottom-nav button `{ key: "brainstorm", icon: "📖", label: "Inspirations" }` (`App.jsx:12096` mobile, `App.jsx:10243` desktop) sets `activeBottomTab = "brainstorm"`, and the render branch is `activeBottomTab === "brainstorm"` (`App.jsx:11942`).
- The public URL is `/trip/:id/magazine`. `parseUrl()` translates the slug at the parse boundary: `const tab = tabMatch[2] === "magazine" ? "brainstorm" : tabMatch[2]` (`main.jsx:91-98`). The reverse mapping happens in the URL-sync effect: `activeBottomTab === "brainstorm" ? "magazine" : activeBottomTab` (`App.jsx:6604-6608`). So the hint in CLAUDE.md is accurate — URL and state key deliberately differ, translated in exactly two places.
- Pre-IG (route-selection phase) there is a _separate_ magazine area on the `screen === "brainstorm"` page, driven by `pretripTab === "magazine"` (`App.jsx:11239`, labelled "Inspirations" in the pre-trip bottom nav).
- Both phases share a sub-tab strip `MagazineSubTabStrip` with `inspirations` | `magazine` keys (`App.jsx:4865-4908`); `magazineSubTab` defaults to `"inspirations"` (`App.jsx:6782`), i.e. **Inspirations is the default sub-tab**, which is why the nav button is labelled "Inspirations" even though the state key says magazine/brainstorm.

## Opening the Magazine — lazy-loading strategy

State lives at App level:

- `deepDiveCacheApp` — `{ [cityName]: "loading" | "error" | deepDiveObject }`, hydrated from `trips.magazine_digest` on mount (`App.jsx:6854-6857`).
- `destResearch` — `{ digest, loading, errored, hasLoaded }`, hydrated from `trips.inspirations_digest` (`App.jsx:6946-6952`). Because `main.jsx` loads the trip with `SELECT *`, a revisit renders both instantly with zero network calls.

**Eager pre-load on RG completion** (`App.jsx:7073-7099`): when the first batch of routes arrives (`pretripRoutes.length > 0`), a one-shot effect (guarded by `hasEagerLoadedRef`, `App.jsx:7069`) fires:

1. `loadDestinationResearch()` — Inspirations, if not already loaded.
2. Deep dives for up to **2 country-level destinations** (`resolveCountriesForMagazine(...).slice(0, 2)`, `App.jsx:7081-7083`). Fallback for "Help me decide" trips: the first city of the first undismissed route (`App.jsx:7086-7096`).

Note the actual code loads _destination/country cards_, not "destination + top 2 cities" — the per-city cards below are not eagerly fetched.

**Everything else is viewport-lazy:**

- Each `CityCard` registers an `IntersectionObserver` (rootMargin 240px) that calls `onVisible` → `loadCityDeepDiveApp(city)` when the card nears the viewport (`Magazine.jsx:367-382`, wired at `App.jsx:11128` pre-trip and `App.jsx:3505` in-trip).
- City hero photos have their own observer (rootMargin 200px) so photo fetches start one-by-one as the user scrolls, not all at once (`Magazine.jsx:318-333`).
- Highlight-card photos use a third observer (rootMargin 400px) (`Magazine.jsx:682-696`).
- `loadCityDeepDiveApp` dedupes via `deepDiveCacheRef` (skip if loaded) and `deepDiveInflightRef` (skip if a request for that city is already in flight) (`App.jsx:6878-6884`).

**Card lists:** pre-trip Magazine renders one card per destination from `resolveDestinationsForMagazine` (`App.jsx:961-997`) followed by one per unique undismissed-route city (`App.jsx:11060-11077`, `11209-11215`), optionally filtered to a single route's cities via `magazineFilterCities` ("Explore this route's destinations", `App.jsx:10984-10986`). In-trip, `BrainstormView` groups itinerary days by city and renders destination cards (highlights = deep-dive `moreSights`) plus city cards (highlights = itinerary activities + wishlist + tier-2 brainstorm items, deduped by title) (`App.jsx:3406-3495`). Items already in the itinerary sort first and get a ✓ badge + "In your itinerary" pill (`App.jsx:3487-3495`, `Magazine.jsx:762-783, 913-929`).

## `city-deep-dive` edge function

`supabase/functions/city-deep-dive/index.ts`:

- **Model:** `claude-haiku-4-5-20251001`, `max_tokens: 2048`, non-streaming (`index.ts:84-89`).
- **Guards:** kill switch → `authenticateUser` (401) → `requireMinCredits` (default min 1.0 → HTTP 402, `_shared/credits.ts:145-155`) → per-user rate limit (`index.ts:47-57`).
- **Request:** `{ city, country, travelMonth, styles, budget, notes, tripDays, tripId }` (`index.ts:60-69`). The App-level caller builds `country` from the trip destination and month from `start_date` (`App.jsx:6886-6913`); note it does not send `tripDays` (only the legacy in-`BrainstormView` fallback loader does, `App.jsx:1839`).
- **Response schema** (`SYSTEM_PROMPT`, `index.ts:17-40`): `writeup`, `foodSpecialties[]`, `weather`, `gettingAround`, `etiquette[]`, `didYouKnow`, `moreSights[]` — these map 1:1 to the CityCard/deep-dive sections above.
- **Anti-hallucination approach** is prompt-level, for `moreSights` (`index.ts:36-38`): every place "MUST be real and verifiable", only places with a Wikipedia article or Google Maps listing, never invent/combine names, includes a concrete negative example ("Uzuki Matsuri Valley" as a hallucinated name), prefer well-known places, and `geocode` must be the exact real-world Wikipedia/Maps name (e.g. title "Golden Pavilion" → geocode "Kinkaku-ji"). There is no post-hoc verification in this function — although in practice the Wikipedia photo lookup and Maps links act as a soft reality check downstream.
- **Credits:** `deductCredits` fire-and-forget after the call, plus a separate fire-and-forget `llm_usage` insert (`index.ts:100-126`). If the user is out of credits the function returns 402 **before** the LLM call; both frontend loaders route the 402 through `handleGatedResponse` (opens the paywall) and mark the city `"error"` so the skeleton stops (fixed 2026-07-13 — previously the 402 was swallowed silently).
- **Caching/persistence:** the function itself is stateless — no server-side cache. Persistence is client-side: `loadCityDeepDiveApp` writes the whole `deepDiveCacheApp` map to `trips.magazine_digest` (fire-and-forget `supabase.update`, `persistMagazineDigest`, `App.jsx:6864-6876`), once with the text content immediately and again after background photo attachment (`App.jsx:6917-6933`). Editing a trip with destination changes clears both `magazine_digest` and `inspirations_digest` (`App.jsx:7570-7587`).
- Parsing: slices the first `{` to the last `}` and `JSON.parse`s; on failure returns `{ error: "parse_failed", raw }` (`index.ts:128-135`).

## Photo sourcing (`src/photos.js`)

Magazine cards never call a paid photo API — everything except hotels comes from Wikipedia/Wikimedia Commons:

- **Queue:** all Wikipedia/Commons requests go through `wikiQueuedFetch = makeQueue(400, 2)` — **2 concurrent, 400ms stagger** (`photos.js:82`; CLAUDE.md's "3 concurrent / 300ms" is stale). The queue honors 429 `Retry-After` with a global cooldown (`photos.js:28-80`).
- **`_fetchPhoto(geocode, city, type)`** (`photos.js:121-345`) — 4-tier lookup: (1) Wikipedia exact-title `pageimages` with redirects, including city-stripped and POI-suffix-stripped candidates ("Senso-ji Temple" → "Senso-ji"); (2) same relaxed rule for variants; (3) Wikipedia full-text search, top 5, person pages filtered by description regex, filename-relevance check; (4) Wikimedia Commons file search. Filters: `_isPortrait`, `BAD_PATTERNS` (svg/maps/flags/logos/panoramas...), and `_usedPhotoUrls` global dedup so the same photo never appears on two cards. Hotels bypass all of this via `places-proxy?action=hotel-photo`.
- **In-flight coordination (the recent race fix):** `_photoCache[key]` is set to the `_PHOTO_IN_FLIGHT` symbol on entry; concurrent callers get `null` immediately instead of duplicate fetches (`photos.js:131-138`). Components handle this by checking `_photoCache[key] === _PHOTO_IN_FLIGHT` and scheduling **one retry after 4s** — by then either the parent has attached `photo_url` or the in-flight fetch has populated the cache (`Magazine.jsx:335-365` CityCard, `Magazine.jsx:704-744` MagazineHighlightCard). There is no serialized "Magazine fallback queue" anymore; lazy `IntersectionObserver` triggers + the shared queue + in-flight retry replaced it.
- **`attachPhotosToMoreSights(data, city)`** (`photos.js:357-376`): after a deep dive returns, App fetches photos for each `moreSights` entry **sequentially** in the background (splitting combined names like "Bhadra Fort and Teen Darwaza"), then re-persists the digest with `photo_url`s baked in (`App.jsx:6924-6933`). Cards pick up `item.photo_url` reactively (`Magazine.jsx:697-703`) — so on revisit, moreSights photos render instantly from `magazine_digest` without hitting Wikipedia.

## Inspirations sub-tab

### Frontend flow

- **Auto-load triggers:** (1) eagerly when RG's first routes land (`App.jsx:7077-7079`); (2) lazily whenever the Inspirations view becomes visible and `hasLoaded` is false — covers opening an existing itinerary directly on the Magazine tab (`App.jsx:7101-7126`). There is no opt-in CTA; the section auto-loads, and only failures show a "↻ Try again" button (`Magazine.jsx:1468-1490`).
- **Request** (`loadDestinationResearch`, `App.jsx:6964-7063`): POST `/functions/v1/generate-destination-research` with `{ destinations, notes, startDate, tripId, refinement, bypass_cache }`. Destinations come from `resolveInspirationDestinations` (`App.jsx:1025-1072`): explicit form destinations → trip destination split on `→` only (not `,`, so "Bali, Indonesia" stays one destination) → for Help-me-decide, destination-level names extracted from route titles (max 4).
- **402 handling:** non-OK responses read the body for a useful error; `res.status === 402` calls `openPaywall("Inspirations couldn't load")` (`App.jsx:7011-7014`) — the standard `CreditsOverlay` bottom sheet. (This path uses `openPaywall` directly, not `handleGatedResponse`.)
- **Persistence:** the returned digest is written to `trips.inspirations_digest` fire-and-forget (`App.jsx:7036-7046`), so any device shows results instantly on revisit.
- **Load more** (`Magazine.jsx:1557-1709`, wired `App.jsx:11034-11040`): plain "Load more" calls with `append: true, bypassCache: true` (fresh batch, skip the 30-day cache); "Focus on a specific angle →" reveals a free-text refinement input (e.g. "hiking, budget travel, solo female") which is sent as `refinement` and _does_ use the cache (each refinement gets its own cache entry). Appended results are merged and **deduped by URL** (`dedupeByUrl`, `App.jsx:6955-6957`, `7021-7028`).
- **Rendering** (`InspirationsSection`, `Magazine.jsx:1372+`): dedupes by author, then interleaves videos and articles so vlogs are spread throughout (`Magazine.jsx:1382-1401`). Each `InspirationCard` shows outlet/author + month, title, blurb, and a Read/Watch link. YouTube URLs get an in-app **lite embed**: static `i.ytimg.com` thumbnail + play button, swapped for a `youtube-nocookie.com` autoplay iframe only on click (`Magazine.jsx:1174-1201, 1244-1318`). External links open via Capacitor's in-app browser on Android, `window.open` on web (`Magazine.jsx:7-22`).

### `generate-destination-research` edge function

`supabase/functions/generate-destination-research/index.ts`:

- **Model:** Haiku 4.5 (`claude-haiku-4-5-20251001`), `max_tokens: 4000`, with the server-side `web_search_20250305` tool at **`max_uses: 6`** (`index.ts:436-447`). CLAUDE.md's "max 4 uses" is stale — the comment at `index.ts:439-441` documents the bump to 6 so Haiku can run separate article-focused and YouTube-focused queries (cost ceiling 6 × $0.01).
- **Pipeline on each request:**
  1. Guards: kill switch, auth, rate limit. `requireMinCredits(user, cors, MIN_CREDITS = 8)` is _computed_ up front but **only enforced on cache miss** (`index.ts:312-317, 410-411`) — cache hits work even at 0 credits.
  2. **Tag extraction:** a tiny Haiku call (`max_tokens: 200`) maps the trip notes onto a bounded vocabulary of 20 tags (food, scuba, hiking, ... vegetarian), max 5, never invented (`TAG_SYSTEM_PROMPT`, `index.ts:120-128`, `extractTags` `index.ts:230-293`). Tags drive the cache key.
  3. **Cache key:** `sha1(JSON.stringify({ d: destinations, t: tags, m: monthBucket, v: 5, r: refinement }))` (`index.ts:364-372`). `monthBucket` is a two-month bucket from `startDate` ("jan-feb", ... or "any", `index.ts:130-151`); `v` is a manual version bump for breaking prompt changes; `r` scopes each refinement phrase to its own entry.
  4. **Cache lookup** in the `destination_research` table (migration `20260527000003_destination_research_cache.sql`) with a 30-day TTL — a valid hit returns `{ digest, cached: true, tags, generated_at }` with **no LLM search call and no credit charge** beyond the tag extraction (`index.ts:374-408`). Skipped when `bypass_cache` is set.
  5. **Cache miss:** the main Haiku + web_search call. The system prompt (`index.ts:66-118`) demands 5–10 entries from **named individual creators** (personal bloggers, named YouTubers, Substack writers, journalists) published in the last 24 months, first-person voice preferred, one entry per creator, and explicitly blocks listicle sites, aggregators, tourism boards, AI-written and SEO-farm content. Anti-fabrication rule: every URL "MUST be one that web_search actually returned in this session" — never constructed or guessed; better empty than fake.
  6. **Parse** via a 4-strategy `tryParseJson` (raw → strip fences → outermost braces → find `{"inspirations"`) (`index.ts:184-228`); a parsed object with no `inspirations` array degrades to an empty digest rather than a 500 (`index.ts:459-475`).
  7. **Persist:** upsert into `destination_research` keyed on `cache_key` with `expires_at = now + 30 days` and the `web_search_count` (`index.ts:487-503`); fire-and-forget `llm_usage` log; `deductCredits` for the **combined** tokens of tag-extraction + main call (`index.ts:519-533`).
- **Response digest shape:** `{ destinations, tags, monthBucket, inspirations[], place_insights[], sources[], generated_at }` (`index.ts:477-485`). `inspirations[]` entries carry `type ("article"|"video"), title, author, author_type, outlet, date (YYYY-MM), url, blurb`. The frontend currently renders only `inspirations`; `place_insights`/`sources` are stored but unused in the UI.

Note the two-layer caching: the `destination_research` table is a **global, cross-user** 30-day cache (RLS: service-role write, any authenticated read), while `trips.inspirations_digest` is the per-trip snapshot the UI hydrates from.

## Credit gating summary

| Path                                                     | Gate                                                      | Frontend on 402                                                                      |
| -------------------------------------------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `city-deep-dive`                                         | `requireMinCredits` (min 1.0) + `deductCredits` post-call | `handleGatedResponse` opens the paywall; city marked `"error"` so the skeleton stops |
| `generate-destination-research` (cache hit)              | none (tag-extract call still runs, uncharged to the gate) | n/a                                                                                  |
| `generate-destination-research` (cache miss / load more) | `requireMinCredits` min 8 + `deductCredits` post-call     | `openPaywall("Inspirations couldn't load")` (`App.jsx:7011-7014`)                    |

Both functions also enforce auth (401), the per-user rate limit (429, 20 calls/min default), and the global LLM kill switch from `_shared/credits.ts`.
