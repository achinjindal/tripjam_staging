2 · Information architecture & permissions

New surfaces (additive): the Route Overview block (top of the Itinerary tab) and the Route Editor sheet. Untouched: "Explore other plans" (alternatives, Select flow, Show-me-more — linked from the overview, otherwise exactly as today), Magazine, day cards, chat bar, tab bars, Story mode. Nothing is removed.

Ownership rule: the overview/editor own the CHOSEN route; Explore other plans owns the alternatives. The two never render each other's content.

Permissions: editing requires write access to brainstorm_items. On prod today that is owner-only; member co-edit arrives with the pending co-edit migration (PR #1). Until it lands: members see the overview normally, and "✎ Edit route" opens the sheet read-only (steppers/move/remove hidden, footer: "Only {owner} can edit the route for now"). Never render an Apply that would silently no-op — that is the known bare-write hazard. After co-edit lands, all members edit; no viewer role in v1.

3 · Data model (the load-bearing section)

3.1 What exists today

A route row in brainstorm_items stores city (one display string) and data.days — an array of free-text day strings with **bold** city prefixes. There is no per-stop structure and no nights field. Everything below has to create one.

3.2 The new structured field

data.stops = [
  { city: "Ziro Town",     nights: 2 },   // order = route order
  { city: "Hapoli",        nights: 1 },
  { city: "Hong & Siiro",  nights: 3 },   // free text OK — combined stops pass through
  { city: "Kile Pakho",    nights: 2 }
]

Written by: (a) the editor's Apply (always), and (b) RG going forward — the RG prompt adds a machine-readable stops array per route so new trips are structured from day one. city strings are free text; autocomplete-picked cities also carry {lat, lng} when geocoded (for the distance warning only — never required).

3.3 Derivation ladder for existing routes (no migration)

On trip open, if the selected route has no data.stops: (1) parse the **bold** prefixes of data.days into a stop chain — consecutive same-prefix days collapse into one stop; nights inferred from run length, with the trip's final day contributing 0. (2) If parsing yields ≥1 stop whose nights sum exactly to trip nights, render it (derived in memory, not persisted). (3) Otherwise the overview hides entirely for that trip — no guessing from the generated days table. The editor persists the real structure on first Apply. The rejected alternative (deriving from generated days) would seed the editor with a chain the user never chose, since IG deviates from outlines routinely.

3.4 The nights model — defined once, used everywhere

Budget = trip nights = trip days − 1. Oct 3–Oct 11 is 9 days, 8 nights. The final day belongs to the last stop's D-range but consumes no night (departure day). Stepper minimum 1 night — the editor models overnight bases only; day-trips and pass-through stops ("4 hours in Nara en route") remain IG's job inside a base's days, as RG already writes them. Stop count 1–8 (8 is our product cap; RG's prompt only says "realistic for the duration"). Two sources of truth, deliberately: D-ranges in the overview derive from the actual generated days (ground truth for "which day am I on"); nights in the editor come from data.stops (ground truth for the budget). When IG deviates from the outline, D-ranges stay honest and nights stay editable — the two are labeled distinctly and never summed against each other.

3.5 Write-back (net-new, atomic)

One explicit update to the selected route row, fired only when the user accepts the replace confirmation, in the same action that starts the rebuild: city (regenerated display chain "Ziro Town → Hapoli → …"), data.stops, data.days (outline regenerated from stops as "**City** — N nights" lines so legacy readers stay coherent), last_modified_by, last_modified_at. Never on editor close, never at checkpoint/Pre-IG. The chat edit_route action must also start stamping last_modified_* (today it omits them — a pre-existing gap this feature closes). IG receives the edited chain through its normal route-payload path. No reliance on the votedItems ride — verified in code: that path only syncs the selected flag on existing trips, it never writes shape.

5 · Flows, exhaustively

5.1 Glance & zoom (no cost)

Open trip → S1 overview → tap segment → scroll to that stop's first day → scroll past overview → sticky strip → tap strip → re-expand at top. Active-trip window: auto-collapsed, list opens at today.

5.2 Edit & rebuild (costed, solo trip)

S1 "✎ Edit route" → S2 editor (snapshot of the stored route taken on open) → free edits, ledger enforcing balance → Apply "Rebuild itinerary from this route" (helper: "uses credits" — no invented number; the estimator is v2) → editor closes → Pre-IG sheet (existing) → Replace confirmation with the existing parameter diff plus a route-shape line ("Route: 4 stops → 5 stops · +Talley Valley · Hapoli 1→2N") → on accept, the §3.5 write-back fires and IG rebuilds (existing streaming UI owns progress; overview hides during streaming, re-renders when days land) → activity: route_edited row + existing itinerary_generated milestone.

5.3 Shared trip variant (v1: notify, don't poll)

Same funnel; the checkpoint appears with rebuild-flavored copy ("Rebuild the itinerary around the edited route? Your group's plan will be replaced — everyone will see the change.") offering Rebuild now / Cancel — no "Ask the group" poll in v1. Reason (review blocker): pending edits live only in the proposer's session, so a poll would reference a route no one else can see and would dangle if the proposer leaves. Co-members learn via realtime route-row update (overview refreshes), route_edited + itinerary_generated in the feed and while-you-were-away digest. The poll returns in v2 by persisting the proposal as a data.pending_edit draft on the route row (survives sessions, renderable in the poll card). A successful rebuild refreshes the rework-nudge marker (counts as incorporating member styles).

5.4 Abandon, failure & concurrency

Path Behavior
Close with pending edits Confirm sheet: "Discard route edits? Your itinerary hasn't changed." Discard / Keep editing. ESC / Android back / scrim all route through it.
Cancel at Pre-IG or Replace step Funnel aborts; nothing persisted (write-back fires only at replace-accept). Editor reopens with pending edits intact (session memory).
402 at rebuild Existing credit paths: personal → paywall; shared pool empty → fork paywall (incl. Ask-the-group top-up). Write-back has already fired (it rides replace-accept), so the route row keeps the new shape and the recovery row below applies once credits exist. Edits are no longer "pending" — they're the route.
IG fails / times out Existing IG failure handling. Route row carries the new shape; overview renders the new chain with "Rebuild didn't finish — Try again" (tappable; re-enters IG with the same parameters, no re-confirm).
Editor during IG streaming "✎ Edit route" disabled, labeled "Rebuilding…". In the zero-days recovery state the editor opens normally — editing the route is a legitimate recovery move.
Concurrent editors (shared) v1: last completed rebuild wins; the feed narrates both. The editor writes last_modified_by/at so v2's stale-snapshot banner ("{name} just changed this route — reopen to see the latest") lands on real data; the banner itself is deferred while realtime tiers are dark.
Autocomplete offline / geocode fail Add-a-stop accepts free text (IG handles names); the geo-warning simply doesn't render. No hard Places dependency.
Overview data unavailable No data.stops and derivation fails → hides. Offline (route rows aren't localStorage-cached) → hides. Legacy no-routes trips → hides. Always silently; the itinerary renders exactly as today.

5.5 Add a stop, precisely

Tap ＋ → inline row with region-biased city autocomplete (Places proxy) → chosen city appends as a NEW row (moss dashed), 1 night, ⌃⌄ controls → ledger goes over → user rebalances → optional inline geo-distance warning when the city geocodes far from the route centroid (warn-only; km, the app's convention). Free text allowed when autocomplete fails. Combined stops ("Hong & Siiro") pass through untouched — the model never splits or validates city strings. The stop has no real existence until Apply: IG invents its days, hotel, and both transit legs during the rebuild. Min 1 stop after removals; max 8.
