In-context "what is this place?" for route cards. Two tap paths, one source of truth — the route's structured stops/city data: the first mention of each town in the day text is dotted-underlined (read path), and a "Places on this route" chip row indexes every town with nights/day-trip metadata (index path). Tapping either opens a peek: Wikipedia lead image + first paragraph (free, no LLM), a trip-context line computed from the routes, and two escapes (Trippy · Magazine). Bold stays pure emphasis — the underline alone means tappable. Try it: tap an underlined town or a chip in the phone.

What's peekable (Rev 6 — two paths, one source). A place gets a peek only if understanding it could change which route you pick: overnight bases and day-trip destinations — the route's stops / city fields. Two ways in, same list: the read path — the first mention of each town in the day text is dotted- underlined, so curiosity is served mid-sentence — and the index path — the chips row, one chip per town with nights / day-trip metadata. Linking is matched from the city list (word-boundary, case/diacritic-insensitive), never from bolding: bold stays pure emphasis, the underline alone means tappable, and a linked town inherits whatever weight its sentence gave it. Re-mentions ("back to Galle") stay plain — repeat taps are what chips are for. POI highlights (Coconut Tree Hill, Galle Fort) and hotels are not peekable here — they're the route's evidence, not its skeleton; their moment is the itinerary stage.
Sheet in context. The peek overlays the whole Route screen — scrim covers header, tabs and the Build CTA; the sheet caps at 82% height so the screen behind stays visible. Three exits: ✕ button (top-right), scrim tap, swipe-down on the grab handle. Nothing behind is disturbed on close — scroll position, selection and vote state persist.
Interaction rules. Route cards are click-to-vote — text links and chips call stopPropagation so a tap never toggles the vote. Opening fires posthog place_peek_open { place, source: text | chip, kind: base | day_trip, route_id, wiki_hit } — source tells us which path earns its keep.
Magazine prefetch (Rev 2). The first peek open for a city fires loadCityDeepDive(city) in the background — fire-and-forget, deduped by the existing cache. By the time the user taps "More in Magazine" the deep dive is warm and the tab opens instantly, anchored at that city. Since only towns are peekable, every peek maps 1:1 to a deep dive.
Why city-list matching, not bold-driven linking? RG bolds sparingly (first mention only, sometimes the hotel instead of the town), so bold-anchored links would have arbitrary coverage — a 3-night base could lack any tap point in the text. Matching against the city list makes coverage principled: every town gets exactly one text link (its first mention, wherever and however it appears) plus exactly one chip. If a town somehow never appears in prose by name, the chip still guarantees access.
Content source. Wikipedia REST page/summary via the existing serialized queue in photos.js (2 concurrent / 400ms) — the same call the photo pipeline already makes, we just stop discarding extract. Lookup tries "Ella" → "Ella, Sri Lanka" (suffix from trip destination), rejects disambiguation pages, caches in module + localStorage. Zero LLM cost, works offline once cached.

4 · Build spec (v1)

  • src/places.js — fetchPlaceSummary(name, destinationContext): Wikipedia REST summary through the exported photos.js queue; candidate order [name, `${name}, ${destination}`]; reject type:"disambiguation" / "may refer to"; module + localStorage cache; returns { title, extract, image, url } | null.
  • src/PlacePeek.jsx — sheet (mobile) / popover (desktop via useViewport); props: { place, tripContext, onAskTrippy, onOpenMagazine, anchorEl }. Instant open with title + context, extract/image stream in.
  • RouteCard chips (index path): one chip per peekable town. Base chips from item.stops (nights), day-trip chips from city − stops (dashed style). Falls back to parsing item.city alone for pre-stops saved routes (all chips unlabeled then).
  • RouteCard text links (read path): after the existing ** bold split, scan the plain segments AND bold segments for city-list town names (word-boundary regex per town, case/diacritic-normalized); wrap the first match per card per town in a tappable span that inherits weight/color and adds only the dotted underline. Later mentions untouched. Both links and chips call stopPropagation (cards are click-to-vote).
  • Trip context — computed in BrainstormView from all undismissed tier-1 items: for each route, is this place a base (nights from stops), a day-trip / highlight (named in days text), or absent.
  • Magazine prefetch — first peek open per city calls loadCityDeepDive(city) fire-and-forget (existing cache dedupes repeats); non-city highlights resolve to their parent city via the route's city list. "More in Magazine" then opens warm.
  • Telemetry — place_peek_open { place, source, route_id, wiki_hit } · place_peek_cta { cta: trippy | magazine }.
  • No DB changes, edge functions, migrations, or RG prompt changes. Works on already-saved routes.
